nginx / Caddy, installateur, sauvegardes), dépendances. Le serveur de production n'était pas
joignable depuis l'environnement d'audit : les vérifications côté serveur sont listées en
section 3, avec les commandes à lancer.

## 2. Corrigé dans cette livraison

| # | Gravité | Problème | Correction |
|---|---|---|---|
| 1 | Élevée | **Import des sites** : une redirection d'un site public pouvait envoyer le serveur vers une adresse interne (127.0.0.1, 169.254.169.254…) sans nouveau contrôle. | Chaque requête, redirections comprises, est revérifiée ; adresses non publiques refusées ; 5 redirections et 2 Mo par page au plus. Test ajouté. |
| 2 | Moyenne | **Base de connaissances** : un utilisateur connecté pouvait lire n'importe quel fichier `.md` du serveur en donnant un chemin absolu. | Lecture limitée au dossier de la base (chemins absolus, `..` et liens vers l'extérieur refusés). Test ajouté. |
| 3 | Moyenne | **Formulaires** : le cookie `SameSite=Strict` n'écarte pas une requête venue d'un autre sous-domaine d'ibigsoft.com (même « site »). | Tout formulaire venant d'une autre origine que le tableau de bord est refusé (403). Test ajouté. |
| 4 | Moyenne | **En-têtes de sécurité** absents de l'application (dépendance totale à nginx ; pas de politique de contenu, pas de HSTS avec nginx). | Ajoutés par l'application : `Content-Security-Policy`, `X-Frame-Options`, `nosniff`, `Referrer-Policy`, `Permissions-Policy`, HSTS en HTTPS. Vérifié sur les 20 pages. |
| 5 | Faible | **Boîtes mail** : l'adresse était insérée dans du code JavaScript (confirmation de retrait). | Confirmation par attribut de données, sans code généré. |
| 6 | Faible | **Connexion** : la mémoire des tentatives échouées grossissait sans limite avec des adresses inventées. | Nettoyage automatique au-delà de 5 000 adresses. |
| 7 | Faible | **Image Docker** : pip et setuptools anciens (vulnérabilités connues, sans effet sur l'agent en fonctionnement). | Mis à jour à la construction. |
| 8 | Moyenne | **Sauvegardes** : le script existe mais l'installateur ne le programmait pas. | L'installateur ajoute la tâche quotidienne (2 h 15). Serveur déjà installé : voir 3. |
| 9 | Grave (affichage) | **Boîtes mail et Services** affichaient leur formulaire 2 à 3 fois (gabarit abîmé). | Corrigé lors de la refonte (commit 9abc2fc), test ajouté. |

## 3. À vérifier sur le serveur (5 minutes)

Dans `/opt/ibig-ia` :

```sh
# a. Adresse en HTTPS : conditionne le cookie « Secure » et HSTS
grep IBIG_DASHBOARD_URL .env          # doit afficher https://agents.ibigsoft.com

# b. Sauvegarde quotidienne programmée ? (sinon, la ligne suivante l'ajoute)
crontab -l | grep sauvegarde || (crontab -l 2>/dev/null; echo "15 2 * * * cd /opt/ibig-ia && ./deploy/sauvegarde.sh >> /var/log/ibig-sauvegarde.log 2>&1") | crontab -
./deploy/sauvegarde.sh && ls -lh /var/backups/ibig-agent | tail -3

# c. Fichier des secrets lisible par root seulement
chmod 600 .env && ls -l .env

# d. Pare-feu : seuls 22, 80 et 443 ouverts
ufw status

# e. En-têtes de sécurité (après mise à jour)
curl -sI https://agents.ibigsoft.com/login | grep -iE 'strict-transport|content-security|x-frame'

# f. Diagnostic complet de l'agent
docker compose exec agent ibig-agent diagnostic
```

## 4. Ce qui manque encore (par priorité)

### Priorité haute
1. **Copie des sauvegardes hors du serveur** (autre hébergeur ou stockage objet) et **chiffrement** de ces copies : aujourd'hui une sauvegarde contient la base et le fichier `.env` (clé du coffre) ensemble. Un serveur perdu ou volé emporte tout.
2. ✅ **Fait (1er oct.)** — **Suivi des tâches planifiées dans le tableau de bord** : relève des mails, publications programmées, rapports… Une tâche en échec n'apparaît que dans les journaux Docker ; il faut une carte « Santé des tâches » (dernière exécution, dernier échec) et une alerte à la direction après plusieurs échecs.
3. **Versions des dépendances figées** (fichier de verrouillage) : chaque `docker compose up --build` peut installer une nouvelle version majeure (FastAPI, Anthropic…) et casser l'agent sans modification du code.

### Priorité moyenne
4. ✅ **Fait (1er oct.)** — **Changer son mot de passe depuis le tableau de bord** (aujourd'hui : ligne de commande sur le serveur uniquement), et gestion des comptes (créer, désactiver) pour l'administration.
5. **Double authentification** (code à usage unique) pour les comptes admin et direction.
6. ✅ **Fait (1er oct.)** — **Déconnexion effective** : la session reste valable 12 h même après « Se déconnecter » ou un changement de mot de passe (session sans état côté serveur). Ajouter un numéro de version de session par compte.
7. **Limite de tentatives par adresse IP** (en plus de la limite par compte), avec lecture de l'IP réelle transmise par nginx (`--proxy-headers`).
8. **Surveillance de disponibilité** externe (ex. UptimeRobot sur `/health`) avec alerte SMS ou mail.

### Priorité basse
9. Messages de confirmation passés dans l'adresse (`?msg=`) : un lien piégé peut afficher un faux message dans le tableau de bord (sans autre effet). Les signer ou les passer par cookie.
10. Rotation de la clé `IBIG_SECRET_KEY` : prévoir une procédure (elle chiffre le coffre et signe les sessions).
11. Journaux d'application : peu de traces hors erreurs ; ajouter des journaux structurés (connexions, décisions, échecs d'envoi) consultables sans accès au serveur.
